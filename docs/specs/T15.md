# T15: ver y editar borradores de Zernio

## Qué se hace
- En `/cola`, cada borrador de TikTok o Instagram (origen Zernio, estado `borrador`, con `zernioPostId`) se puede
  editar: el texto y la fecha y hora (Bogotá).
- El cliente de Zernio gana **un único** método de escritura: `editarBorrador(id, { contenido?, programadoPara? })`,
  que hace `PUT /v1/posts/{id}` con un cuerpo armado por una función pura que **siempre** pone `isDraft: true` y solo
  copia `content` y `scheduledFor` (ISO con zona). Nunca crea, programa, publica ni cambia `isDraft`.
- Antes de enviar, una confirmación que muestra qué cambia (antes → después), en qué red y para cuándo, con el botón
  "Guardar borrador". Sin confirmación no se envía.
- La acción del servidor exige sesión, valida con zod, revisa que la publicación local siga siendo un borrador de
  Zernio, llama `editarBorrador`, y si Zernio responde bien actualiza `publicacion.texto`/`programadoPara` locales.
- Facebook no se edita: se muestra "Solo en Meta Business Suite" (falta `pages_manage_posts`).
- **Durante la noche no se hace ninguna escritura real:** todo se prueba con `fetch` simulado. El primer uso real lo
  hace Andrés.

## Criterios de aceptación
1. Prueba (rojo primero) de que ninguna combinación de entrada (incluido un objeto con `isDraft: false`,
   `status`, `publishNow`, claves extra o tipos raros) produce un cuerpo sin `isDraft: true` o con otras claves.
2. Con `fetch` simulado: método `PUT`, ruta `/v1/posts/{id}` (id codificado), cabecera de autorización, cuerpo
   correcto; errores sin llaves; un 4xx no reintenta.
3. La acción rechaza una publicación que no es borrador, una de Facebook y una fecha en el pasado.
4. `npm run verificar` y `npm run build` en verde.

## Cómo quedó (implementado)
- **Cuerpo del PUT** (documentación pública de Zernio, `PUT /v1/posts/{postId}`, consultada el 6-nov): campos
  `content`, `scheduledFor`, `isDraft`, `timezone`. "Si se omite `isDraft`, el post conserva su estado"; solo se
  promueve a programado con `isDraft: false` + `scheduledFor`/`publishNow`. Mandamos siempre `isDraft: true`, así que
  nunca se promueve. Cuerpo final: `{ isDraft: true, content?, scheduledFor? }` (ISO UTC). **A confirmar por Andrés en
  el primer uso real:** que Zernio conserve la hora local de Bogotá al recibir `scheduledFor` en UTC (el borrador
  trae `timezone: "America/Bogota"`; no se manda `timezone` para no tocar más campos).
- `http.ts`: GET por defecto; el PUT solo entra por `escritura: { metodo: "PUT", cuerpo }`, y una escritura no se
  reintenta. `zernio.ts`: `cuerpoEditarBorrador` (pura), `editarBorrador`. El tipo `ClienteZernio` (el del recolector)
  omite `editarBorrador`; `ClienteZernioCompleto` lo trae.
- `src/servidor/borradores/editar.ts`: `fechaBogotaADate`, `armarResumen` (pura), `revisarEdicion`, `guardarEdicion`
  (cliente inyectable; la base solo cambia si Zernio responde bien; error genérico "Zernio no aceptó el cambio").
- `/cola/acciones.ts`: `editarBorrador` (paso `revisar` o `guardar` con `confirmar=si`). `consultas/cola.ts`: cada ítem
  trae `texto`, `editable` y `soloMeta`. Componente: `componentes/editar-borrador.tsx`.

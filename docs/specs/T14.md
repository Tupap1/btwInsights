# T14: despliegue en el servidor de BTW

## Qué se hace
1. `docker compose -f docker-compose.prod.yml --env-file .env.produccion up -d --build` (proyecto `btw-insights`),
   unido a la red de Nginx Proxy Manager (`PROXY_RED=proxy-net`, encontrada con `docker inspect nginx-proxy`).
2. **Datos:** se restaura `respaldos/btw_tablero.dump` en la base de producción (`pg_restore --no-owner --no-acl`)
   antes de la primera migración nueva; luego `migrar` aplica las nuevas (T09 en adelante) y los roles. Si el dump
   falla, `importar` con el tar.
3. Una recolección (`curl` interno con el secreto, solo GET a las APIs). `/api/salud` responde
   `{ ok: true, base: "ok" }` dentro de la red.
4. `cron` registra su línea cada hora y `respaldo` deja su archivo (volumen y carpeta del host).
5. Invitación de Andrés (`invitar "Andrés"`): el enlace se deja **solo en la terminal**, nunca en git.

## Criterios de aceptación
- `docker compose ps`: `db`, `app`, `cron` y `respaldo` arriba; `migrar` salió con 0.
- `/api/salud` = ok desde `app` y desde un contenedor en `proxy-net` (`http://<contenedor app>:3000`).
- Una página sin sesión redirige a `https://insights.btw-one.com/entrar`.
- Conteos de la base de producción iguales a los del dump (o mayores tras la recolección).

## Archivos
Ninguno de código; `TRACKER.md` (pasos de NPM y del túnel para Andrés).

## Fuera
Configurar Nginx Proxy Manager o el túnel de Cloudflare (necesitan el inicio de sesión de Andrés).

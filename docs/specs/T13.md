# T13: portabilidad, secretos y documentación

## Qué se hace
- **Portabilidad:** en una base nueva y vacía (no la de uso diario): migraciones desde cero, `importar` con el tar
  de `btw-videos/publicar`, `next build` + `next start` apuntando a ella; `/api/salud` responde y las pantallas
  cargan con los datos importados (21 reels, 49 publicaciones, 2 en "Sin asignar").
- **Secretos en el bundle:** `scripts/revisar-secretos.mjs` busca los **valores** de las llaves y secretos (de un
  archivo de entorno que se le pasa) en `.next/` y, si se le pide, dentro de la imagen `app` (`docker run` +
  `tar`). Nunca imprime un valor: solo el nombre de la variable y el archivo donde apareció. Sale con código 1 si
  encuentra algo.
- **Documentos:** README (correr, actualizar, respaldar), `docs/nube.md` (Neon: solo cambia `DATABASE_URL`; el
  recolector a GitHub Actions o Vercel Cron) y `.env.example` completo (solo nombres).

## Criterios de aceptación
1. `revisar-secretos` probado: con un archivo falso que contiene un valor de prueba, lo encuentra sin imprimirlo
   (prueba unitaria de la función de búsqueda, rojo primero); con el `.next` real y la imagen real, 0 hallazgos.
2. La prueba de portabilidad queda escrita con sus conteos en `docs/specs/T13.md` (sección "Resultado").
3. `npm run verificar` en verde.

## Archivos
`scripts/revisar-secretos.mjs`, `scripts/revisar-secretos.test.ts`, `README.md`, `docs/nube.md`, `.env.example`.

## Fuera
Migrar de verdad a la nube.

## Resultado (6-nov-2026, servidor de BTW)
- **Portabilidad:** proyecto de Compose desechable (`btw-insights-portabilidad`) con las imágenes del commit de T12:
  base nueva y vacía → `migrar` (migraciones 0000 y 0001 desde cero + roles) → `importar` con el tar de
  `btw-videos/publicar` dentro de la imagen `herramientas` → `app`. Quedaron **21 reels, 49 publicaciones (2 en
  "Sin asignar") y 36 lecturas**, igual que con `npm run importar` en el PC. `/api/salud` = `{"ok":true,"base":"ok"}`.
  Con una sesión real (fila en `sesion` con el sha256 del token), `/hoy`, `/videos`, `/videos/10`, `/cola` y
  `/sin-asignar` responden 200 por la red del proxy (`http://btw-insights-app:3000`); sin cookie, 307 a
  `https://insights.btw-one.com/entrar`. Luego `down -v`.
- **Hallazgos que se corrigieron:**
  - el primer arranque fallaba: `pg_isready` por socket daba la base por sana mientras Postgres corría su servidor
    temporal de inicialización → healthcheck por TCP (`-h 127.0.0.1`) en los dos compose;
  - `importar` e `invitar` en la imagen necesitan `node --conditions=react-server` (`docs/despliegue.md` decía otra
    cosa);
  - `invitar` en `migrar` necesitaba las variables `WEBAUTHN_*`.
- **Secretos:** `node scripts/revisar-secretos.mjs --env .env.local --dir .next` → "Sin secretos en .next";
  `--env .env.produccion --imagen btw-insights-app:local` → "Sin secretos en .next y imagen".
